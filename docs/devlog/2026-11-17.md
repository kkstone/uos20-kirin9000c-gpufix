## 23:45 EGL 客户端补 fence 方案（D）实测：不可行，收口
目标: 既然根因是缺 explicit sync, 尝试在客户端 eglSwapBuffers 前插 glFinish 手动补屏障。
探测链(全部实测):
 - Chrome 解析 EGL 不走 dlsym 的 eglSwapBuffers(符号/dlsym hook 均 0 次); 只通过 dlsym 拿 eglGetProcAddress(1次)。
 - 合并进 gbm shim 的 dlsym hook 拦 eglGetProcAddress → 成功: eglSwapBuffers 请求被包装(1次), glFinish 指针拿到(非0)。
 - 但动画页 95 次 commit/damage 期间, 包装的 swap 从没被调用(SWAP-CALL=0)。
 - PID 追踪: swap 指针获取者是 --type=zygote 进程(持5个renderD128 fd=真渲染点), hook 命中不到它真正使用的 swap 调用。
 - 华为 libEGL=libGFX_hisi 导出 eglSwapBuffers/glFinish/eglClientWaitSyncKHR; maleoon_buffer_sharing 私有协议只宣告未bind; buffer 走标准 zwp_linux_dmabuf_v1。
结论: Chrome157 多进程 zygote 架构 + 内嵌 EGL 初始化, 用户态 LD_PRELOAD 垫片无法可靠命中真正渲染 swap 点。D 方案放弃。
所有用户态路线(damage垫片/截图补帧/刷新率/flag A-B/自绘/eglFinish)全部试尽。根因=KWin5.27.331无syncobj协议+华为EGL implicit fence缺陷, 只能靠升级合成器/驱动或换渲染路径(用户已否 zink)。
