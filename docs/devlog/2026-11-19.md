## 10:30 方向1：gdb 逆向 H264High 空指针崩溃 —— 根因 100% 锁定 + patch 点确定
用户选"方向1(攻克空指针崩溃)"。免 root 装 gdb：apt-get download gdb deb → dpkg-deb -x 到 /tmp/gdbpkg/root，
二进制 /tmp/gdbpkg/root/usr/bin/gdb(依赖系统全满足)。用 gdb 解析 core 817231(v8local) 拿到 20 帧完整栈。

### 崩溃机理(铁证)
- #0 pc=0；#1 libxul.so 内 `blr x8`，x8 来自 `ldr x8,[x21,#592]` → **[x21+592]=0 空函数指针**。
- 反汇编崩溃循环(0x7f8bfc849c)：遍历 DRM device list，
  ```
  ldr x0,[x27]        ; device fourcc/name, "1WIH"
  ldr x8,[x21,#592]   ; eglQueryDeviceStringEXT 类函数槽 = NULL
  mov w1,#0x3377      ; EGL attribute(DRM device 扩展)
  blr x8              ; ← 崩溃
  cbz x0,next         ; 返回NULL则跳过该设备
  strcmp(x0,[sp+32])  ; [sp+32]="/dev/dri/renderD128"
  ```
- x27 字符串="1WIH"，x1=0x3377，[sp+32]="/dev/dri/renderD128" → EGL_EXT_device_enumeration/query 路径。
- x21 是 libxul 内嵌的函数表对象：表前端指向 egl-huawei-local/libEGL.so.1+0x4760(eglGetProcAddress)
  及 libGFX_hisi.so+0x11xxxx；表尾 x21+0x220 起连续 NULL，[x21+592]=0。
  根因：华为 EGL 垫片伪装支持 EGL_EXT_device_enumeration，但底层华为库未实现
  eglQueryDeviceStringEXT，函数表尾槽为空 → libva/ffmpeg 在 H264High 枚举时调用 → SIGSEGV。
- 跨 core 验证：773028(v4, 23:52) 与 817231(v8local, 10:13) 均 pc=0 同一崩溃 → 固定，与 RTLD 标志无关。

### patch 点(唯一命中)
- 崩溃指令 `blr x8`=0xd63f0100，libxul.so 文件偏移 **0x4f7d4a8**
  (机器码搜索 4 字节序列 f9400360 f9412aa8 52866ee1 d63f0100 全文件唯一命中；
   与 PT_LOAD 计算 vaddr(0x4f8d4a8)-0x10000 一致)。
- patch 方案：`blr x8`(d63f0100) → `movz x0,#0`(52800000)，使 x0=0 → cbz x0 跳 next device，
  优雅跳过设备查询而非崩溃。华为库该槽恒为 NULL，语义等价，最小侵入可回滚。
- libxul BuildID=0aa1eb5868fdb764bf12c1236c775b7fd9d111f1(FF160)。Mozilla 符号服务器无此 BuildID(404)。

## 19:30 决定性翻案：1.0.15 的 glFinish 同步点也打偏了——只跑 1 次，渲染进程 getfd=0
