## 18:55 【答疑结论】Tile Update Mode=one-copy 与闪屏/果冻无因果
- 用户问 one-copy 是否影响性能、是否造成硬件合成闪/果冻。查证 Chromium cc 源码+graphics-dev：Tile Update Mode 属 **raster 阶段** RasterBufferProvider 选择（GPU raster / One-copy / Zero-copy），one-copy=CPU 光栅化到 staging buffer 再 `CopySubTexture` 上传 GPU 纹理；zero-copy=CPU 直写 CPU-mappable GMB 免拷贝，仅老 ChromeOS/CPU-mappable GMB 平台可用，华为不支持。
- 结论①：one-copy **影响吞吐/卡顿**（元素多、重绘频繁时多一次 CPU→GPU 拷贝更吃带宽），不影响同步；华为平台 Native GpuMemoryBuffers/GMB 支持不完整才落到 one-copy（与 video zero-copy import 被 libEGL 0x3004 拒绝同源），强开 --enable-zero-copy 无效甚至更慢。
- 结论②：one-copy **不是闪/果冻的原因**。铁证：软件合成(--disable-gpu-compositing)下 raster 仍是 one-copy 却不闪——tile 模式没变、变量是 present 路径，故排除。闪/果冻在 present 段（GBM bo→dma-buf→KWin 缺显式 fence 同步），与本段无关。chrome://gpu 显示 one-copy 只是状态报告，不是问题项。
